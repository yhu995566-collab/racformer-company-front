# ChengTech 2026-08-18 Q1-Q5 Training

This path converts the synchronized 1216-frame company capture without
recursively reading directional LiDAR subdirectories. Frame `N` is paired as:

- `lidar_middle/N.pcd`;
- `front120_camera/*-NNNNNN.jpeg`;
- `radar_front/*-NNNNNN.ply`;
- `GT/*-NNNNNN.json`.

The converter reads PCD `binary_compressed` data itself and validates all six
fields. It writes the five model-facing LiDAR values `x,y,z,intensity,ring` to
float32 NPY while retaining timestamp dtype/range in the conversion audit.
LiDAR and GT are already in vehicle coordinates and receive no extrinsic.

Images are undistorted at 1920x1080 using the confirmed front120 rational
distortion coefficients. Radar points share one radar coordinate system, are
transformed to vehicle coordinates, and receive ego-speed compensation before
being written. Radar PLY `rspTimestamp` and `syncTimediff` are interpreted as
microseconds; their sum is validated against the synchronized GT timestamp and
used for radar sweep time lags. The converter verifies whether the serialized
LiDAR float64 timestamp values match GT time as seconds or nanoseconds instead
of trusting a unit label that contradicts the stored magnitude. GT uses
`project_velocity.x/y`.

## Server conversion

```bash
cd ~/hyh/RaCFormer
conda activate racformer_wp

DATA_ROOT=/mnt/diskNvme1/DataSet/radar_camera_GT/2026-08-18-16-01-30
export RACFORMER_COMPANY_PROCESSED_ROOT="$HOME/hyh/company_20260818/processed_racformer"

# First convert ten frames into a disposable audit directory.
python tools/convert_chengtech_20260818.py \
  --data-root "$DATA_ROOT" \
  --out-root "$HOME/hyh/company_20260818/processed_racformer_audit10" \
  --num-sweeps 3 \
  --limit 10

cat "$HOME/hyh/company_20260818/processed_racformer_audit10/conversion_summary.json"

python tools/audit_chengtech_20260818.py \
  --processed-root "$HOME/hyh/company_20260818/processed_racformer_audit10" \
  --frame-index 0 \
  --out-dir outputs/company_20260818_audit10

# Convert all synchronized frames only after the audit is accepted.
python tools/convert_chengtech_20260818.py \
  --data-root "$DATA_ROOT" \
  --out-root "$RACFORMER_COMPANY_PROCESSED_ROOT" \
  --num-sweeps 3 \
  --val-ratio 0.2 \
  --test-ratio 0.0
```

The default chronological split is 973 train / 243 validation frames. The
capture is one short sequence, so these metrics measure same-sequence
generalization and must not be presented as an independent-route result.

Before training, inspect `duplicate_cross_source_candidates` in the summary.
It counts same-class source-0/source-1 centers within one metre but deliberately
does not delete either annotation. A nonzero count requires a GT ownership
decision before training.

Open both audit images and verify that LiDAR projects onto visible surfaces,
radar lies in the same BEV lanes, and source-0/source-1 boxes do not duplicate
the same objects. Repeat the audit for several near/middle/far frames before
running the full conversion.

## Training

Use one Q config at a time. For example, on physical GPUs 1 and 2:

```bash
CUDA_VISIBLE_DEVICES=1,2 torchrun \
  --nproc_per_node=2 --master_port=29701 \
  train.py --config configs/3dh_query_company_20260818_q1.py
```

Replace `q1` and the port with `q2`/29702 through `q5`/29705. Run a one-epoch
smoke test first with:

```bash
CUDA_VISIBLE_DEVICES=1,2 torchrun \
  --nproc_per_node=2 --master_port=29701 \
  train.py --config configs/3dh_query_company_20260818_q1.py \
  --override total_epochs=1 eval_config.interval=1
```

After the smoke test, start the guarded four-GPU sequential queue with one
short command. It keeps global batch size four by using one sample on each of
physical GPUs 4,5,6,7 and starts the next Q only when `torchrun` exits zero:

```bash
bash run_code/run_company_20260818_q1_q5_gpu4567.sh --background
```

## Human quality-control video

Generate a chronological side-by-side video at reduced CPU and disk priority:

```bash
bash run_code/start_company_20260818_quality_video.sh
```

The left panel contains the undistorted camera image and projected GT boxes
only. The right panel contains current-frame LiDAR, radar, and GT in BEV. Point
colors are constant; green boxes are source 0 and red boxes are source 1. The
launcher writes the MP4, first-frame preview, log, and PID under
`/mnt/diskNvme1/hyh/results/RaCFormer/company_20260818_quality_video`.
